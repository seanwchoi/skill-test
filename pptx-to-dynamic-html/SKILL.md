name: pptx-to-dynamic-html
description: 파워포인트(.pptx) 슬라이드를 원본 디자인을 유지한 채 스크롤형 다이나믹 HTML 한 페이지로 변환한다. PPT 등장 애니메이션을 순서대로 재현하고(애니메이션이 없는 슬라이드는 읽는 순서대로 자동 등장 효과를 만들고), 말풍선 도형은 꼬리가 가리키는 영역에 마우스를 올렸을 때만 나타나게 하며, 화살표는 흐르는 형태로 표현하고, 마우스를 올린 요소는 살짝 커지며 하이라이트되고, 마우스 움직임에 따른 가벼운 패럴랙스를 더한다. 사용자가 PPT·파워포인트·슬라이드·제안서·발표자료를 HTML, 웹페이지, 인터랙티브 버전, 링크로 공유할 페이지로 바꿔 달라고 할 때 반드시 사용한다. "덱을 인터랙티브하게", "웹으로 만들어줘", "make my deck interactive", "convert pptx to html"처럼 표현만 달라도 해당된다.

PPTX → 다이나믹 HTML 변환

결과물은 제안발표에 쓰인다. 평가위원이나 고객이 화면에서 덱을 스크롤하며 보고, 발표자는 특정 영역을 짚어 가며 설명한다. 이 맥락이 우선순위를 정한다.

첫째, 원본 디자인이 최우선이다. 슬라이드는 누군가 의도를 갖고 디자인한 것이다. HTML은 같은 덱으로 보여야 하며 재해석하면 안 된다. 위치, 색상, 폰트, 크기를 그대로 유지한다.

둘째, 움직임은 내용을 돕고 내용과 경쟁하지 않는다. 애니메이션은 작성자가 PPT에 설정한 순서를 따른다. 작성자가 애니메이션을 넣지 않은 슬라이드도 정지 화면으로 두지 않고, 읽는 순서대로 차례차례 등장시켜 웹페이지다운 움직임을 준다. 숫자를 읽는 평가위원이 산만해지지 않도록 효과는 가볍게 유지한다.

셋째, 세부 내용은 필요할 때만 보인다. 말풍선에는 보조 설명이 담긴다. 말풍선이 가리키는 영역에 마우스를 올렸을 때만 나타나므로, 누군가 궁금해하기 전까지 슬라이드는 깔끔하게 유지된다.


결과물이 지켜야 할 규칙

말풍선: 슬라이드에 이미 있는 말풍선 도형(사각, 타원, 구름 말풍선 도형, 또는 이름에 "말풍선"이나 "callout"이 들어간 도형)을 쓴다. 기본 상태에서는 숨겨 두고, 꼬리가 가리키는 영역에 마우스가 올라가 있는 동안만 나타나게 한다. 꼬리가 없는 말풍선은 가장 가까운 도형을 대상으로 삼는다. 마우스를 올릴 수 있는 영역에는 작은 점이 깜빡여 발표자가 위치를 알 수 있게 한다. 터치 기기에서는 탭으로 켜고 끈다.

화살표: 흐르는 형태로 표현한다. 화살촉이 있는 연결선과 선에는 밝고 짧은 대시가 시작점에서 끝점으로 이동한다. 블록 화살표(오른쪽 화살표, 쉐브론, 오각형 화살표)에는 진행 방향으로 은은한 빛이 지나간다. 등장 애니메이션이 있는 선은 시작점부터 그려지듯 나타난다.

마우스오버 하이라이트: 화면의 각 요소에 마우스를 올리면 살짝 커지면서 떠오르는 느낌을 준다. 평가위원이 보고 있는 곳을 발표자와 함께 짚을 수 있게 하기 위해서다.
- 단위: 자동 등장 효과와 같은 덩어리를 쓴다. 카드와 그 위의 글자·아이콘, 또는 PPT 그룹 하나가 함께 커진다. 각자 따로 커지면 글자가 박스 밖으로 밀려나 디자인이 깨지기 때문이다. 슬라이드의 30%가 넘는 큰 PPT 그룹(표 전체, 패널 전체)은 묶지 않고 안의 카드별로 나눈다.
- 크기: 덩어리 크기와 상관없이 약 12~16pt 커지도록 3~7% 확대한다. 작은 아이콘도 눈에 띄고 큰 블록도 과하지 않게 하기 위해서다. 확대 중심은 덩어리의 중심이다.
- 하이라이트: 카드(채워진 도형이나 사진)에 부드러운 그림자와 약간의 밝기를 준다. 카드가 없는 글자 덩어리는 요소마다 옅은 그림자를 준다. 조각이 많은 덩어리(벡터 지도 등)는 브라우저가 버벅이지 않도록 그림자 없이 커지기만 한다.
- 제외: 제목, 큰 배경 패널, 슬라이드의 30%가 넘는 덩어리는 하이라이트하지 않는다. 이런 요소는 마우스를 통과시켜 아래 카드가 반응하게 한다. 말풍선 대상 영역에 올리면 말풍선과 하이라이트가 함께 나타난다.
- 등장 효과가 끝난 뒤에만 동작하고, 터치 기기와 ?static에서는 끄며, 동작 줄이기 설정에서는 확대 없이 그림자만 준다. 사용자가 원하지 않으면 --no-hover 옵션을 쓴다.

마우스 효과: 하이라이트 외에는 가벼운 패럴랙스만 쓴다. 배경·장식 층과 콘텐츠 층 두 개가 마우스를 따라 몇 픽셀 움직이고, 말풍선은 조금 더 떠 있는 느낌을 준다. 서로 연결된 도형은 같은 층에 두어 화살표가 박스에서 떨어지지 않게 한다.

애니메이션: 슬라이드가 화면에 들어오면 PPT의 등장 순서(클릭 시, 이전 효과와 함께, 이전 효과 다음에)와 효과(나타내기, 날아오기, 닦아내기, 확대, 분할)를 자동으로 재생한다. 한 슬라이드가 약 5초를 넘지 않도록 시간을 압축한다.

자동 등장 효과(PPT 애니메이션이 없는 슬라이드): build_html.py가 기본으로 만든다. 원칙은 세 가지다.
- 함께 등장하는 단위: PPT 그룹 하나, 그리고 카드·박스 위에 올라간 요소(도형 위 글자, 원 안의 아이콘)는 한 덩어리로 같이 나타난다. 글자만 먼저 떠서 박스와 따로 노는 일이 없게 하기 위해서다.
- 순서: 제목과 큰 패널(슬라이드의 25% 이상)이 먼저, 그다음 위에서 아래, 왼쪽에서 오른쪽 읽기 순서. 덩어리가 많으면 최대 10단계로 묶어 약 2초 안에 끝난다.
- 효과: 기본은 살짝 떠오르며 나타나기. 선은 시작점부터 그려지고, 블록 화살표는 진행 방향으로 펼쳐지며, 큰 사진은 살짝 확대되며 나타나고, 큰 패널은 페이드.
PPT 애니메이션이 하나라도 있는 슬라이드는 작성자의 의도이므로 자동 효과를 섞지 않는다. 사용자가 정지된 슬라이드를 원하면 --no-auto-animate 옵션을 쓴다.

복잡도: 너무 복잡하게 만들지 않는다. 3D 기울이기, 파티클 배경, 작성자가 요청하지 않은 전환 효과, 디자인 수정은 넣지 않는다. 디자인을 개선하고 싶어지더라도 하지 않는다. 평가 기준은 원본에 대한 충실도다. 동작 줄이기(prefers-reduced-motion) 설정 사용자에게는 정적인 버전을 보여 준다.


작업 순서

좌표 계산 같은 반복 작업은 스크립트가 일정하게 처리한다. 덕분에 모든 덱이 같은 방식으로 변환되고, 작업자는 확인과 수정에 집중할 수 있다. 스크립트는 스킬 폴더(SKILL_DIR)에서 실행하고, WORK는 비어 있는 작업 폴더를 쓴다. 다음 명령을 순서대로 실행한다.

    pip install python-pptx lxml pillow playwright --break-system-packages -q   (없을 때만)
    python SKILL_DIR/scripts/extract_pptx.py deck.pptx WORK          (결과: WORK/slides.json, media 폴더)
    python SKILL_DIR/scripts/render_reference.py deck.pptx WORK      (결과: WORK/ref 기준 이미지, 이미지 대체 요소 잘라내기)
    python SKILL_DIR/scripts/build_html.py WORK OUT.html --title "덱 제목"
    python SKILL_DIR/scripts/compare.py OUT.html WORK                (결과: WORK/compare 비교 이미지)

render_reference.py에는 LibreOffice(soffice)와 pdftoppm이, compare.py에는 Playwright Chromium(python -m playwright install chromium)이 필요하다. LibreOffice가 없으면 렌더링 단계를 건너뛴다. 이 경우 차트, 표 같은 이미지 대체 요소가 빠지므로 사용자에게 알린다.

1단계. 추출 요약 읽기
extract_pptx.py는 슬라이드마다 한 줄씩 요소 종류, 인식된 말풍선, 화살표, 애니메이션 개수, 그리고 raster(이미지 대체)로 처리된 요소를 출력한다. 차트, 표, SmartArt, 특이한 도형은 다시 그리지 않고 LibreOffice 렌더링에서 잘라 넣는다. 모양은 정확하지만 이미지가 된다. 사용자가 말풍선이라고 부를 만한 도형이 모두 말풍선 목록에 있는지 확인한다. 빠진 것이 있으면(예: 말풍선처럼 쓴 일반 둥근 사각형) slides.json에서 해당 요소에 "callout": true를 넣고(필요하면 꼬리 위치 "tail": [x, y]를 포인트 단위로 지정) 다시 빌드한다.

2단계. 디자인 충실도를 눈으로 확인하기 (가장 중요한 검수 단계)
WORK/compare/slide-N.png(왼쪽 원본, 오른쪽 HTML)를 모두 열어 본다. 출력되는 diff 점수는 참고용이다. 약 12 이상이면 자세히 본다. 판단은 이미지를 보고 한다. 자주 하는 수정은 모두 slides.json에서 고친 뒤 다시 빌드한다.
- 줄바꿈 위치가 다르다: 대개 폰트 차이다. 런(run)의 font 값을 확인한다. 페이지는 Pretendard, Noto Sans KR로 대체한다. 글자 크기를 조금 조정하는 건 괜찮지만 문구를 고치지는 않는다.
- 도형이 잘못 그려졌다: 해당 요소를 "kind": "raster"로 바꾸고 render_reference.py를 다시 실행한 뒤 빌드한다.
- 요소가 빠졌다: 레이아웃이나 마스터에 있는 요소인지(origin 값), 숨겨진 요소인지 확인한다.
기준 이미지의 한계도 알아 둔다. LibreOffice는 PowerPoint에서는 보이지 않는 그림자를 넣거나 줄바꿈을 조금 다르게 하기도 한다. 애매하면 렌더링보다 XML 값을 믿는다.

3단계. 동작 확인하기
자동 등장 효과는 extract 요약의 "animations 0" 슬라이드에 적용된다. 등장 순서가 이상하면(예: 설명 글이 해당 박스보다 늦게 나옴) 대개 글자 상자가 박스 밖으로 삐져나와 같은 덩어리로 묶이지 못한 경우다. slides.json에서 두 요소에 같은 "group" 값을 넣고 다시 빌드한다.
마우스오버 하이라이트도 몇 군데 확인한다. 카드에 올렸는데 반응이 없으면 대개 위에 투명한 큰 글자 상자가 덮고 있거나, 카드가 큰 PPT 그룹에 묶여 30% 기준을 넘은 경우다. 카드가 커질 때 글자가 따로 놀면 둘이 같은 덩어리로 묶이지 않은 것이므로 slides.json에서 같은 "group" 값을 넣는다.
compare.py는 슬라이드마다 첫 번째 마우스오버 영역에 실제로 마우스를 올려 hover-N.png를 저장하고, 나타난 말풍선 개수를 출력한다. 말풍선이 있는 슬라이드는 최소 한 개가 나타나야 한다. --callouts 옵션으로 한 번 더 실행하면 모든 말풍선이 한꺼번에 보이므로, 각 말풍선이 작성자가 놓은 위치에 있는지 확인한다.

4단계. 전달하기
OUT.html은 이미지가 모두 포함된 단일 파일이다(Pretendard 웹폰트만 CDN에서 불러온다). 환경이 지원하면 아티팩트로 게시하고, 아니면 파일을 보낸다. 사용자에게는 두세 줄로 알린다. 무엇을 변환했는지, 어떤 요소가 이미지로 들어갔는지(차트, 표), 사용법(스크롤 또는 위/아래 방향키, 점이 깜빡이는 영역에 마우스를 올리면 말풍선 표시, 각 요소에 마우스를 올리면 하이라이트)을 알려 준다. 원본에 애니메이션이 없어 자동 등장 효과를 넣은 슬라이드가 있으면 그 사실도 한 줄로 알린다. 확인과 인쇄용 URL 옵션으로 ?static(애니메이션 없이 최종 상태)과 ?callouts(모든 말풍선 표시)가 있다.


판단이 필요한 경우

- 말풍선에 걸린 애니메이션은 무시한다. 말풍선은 원래 마우스오버 전용이다.
- 끝내기, 이동 경로 애니메이션은 적용하지 않는다. 스크롤 페이지에서 요소가 사라지면 다시 스크롤해 올라온 사람이 내용을 볼 수 없기 때문이다. 이런 애니메이션에 의존하던 슬라이드가 있으면 사용자에게 알린다.
- 단락별 애니메이션은 텍스트 상자 전체가 한 번에 나타난다.
- 숨긴 슬라이드는 사용자가 요청하지 않으면 제외한다(--include-hidden 옵션으로 포함).
- 발표자 노트는 표시하지 않는다. 말풍선은 슬라이드 위 도형에서만 가져온다.
- 사용자가 더 많은 움직임을 원하면 템플릿 CSS에 추가하되, 동작 줄이기 설정은 계속 존중하고 디자인은 건드리지 않는다.


파일 구성

- scripts/extract_pptx.py: pptx를 slides.json으로 추출 (테마 색상, 상속된 텍스트 스타일, 그룹, 말풍선 꼬리 끝점, 화살표 끝 모양, 애니메이션 타임라인)
- scripts/render_reference.py: 기준 이미지 렌더링, 이미지 대체 요소 잘라내기
- scripts/build_html.py: slides.json과 assets/template.html로 단일 HTML 생성 (덩어리 묶기: units, 애니메이션 없는 슬라이드의 자동 등장 순서: auto_plan, 마우스오버 하이라이트: hover_plan)
- scripts/compare.py: 원본과 HTML 나란히 비교 캡처, diff 점수, 실제 마우스오버 테스트
- assets/template.html: 페이지 틀. 층과 효과 CSS, 애니메이션 타임라인·말풍선과 하이라이트 마우스오버·패럴랙스·키보드 이동 JS가 들어 있다. 페이지 전체에 적용할 변경은 여기서 한다.
